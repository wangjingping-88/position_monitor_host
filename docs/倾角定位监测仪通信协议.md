# 倾角定位监测仪通信协议

## 版本修改记录

| 版本号 | 日期 | 修改内容 |
| --- | --- | --- |

## 1. 概述

本协议是倾角定位监测仪（以下简称“终端”）与服务器之间的端到端应用层通信协议。WIoTa 网关仅透传完整报文，不解析、不修改协议头、命令或 Data，也不参与请求和响应。

```text
终端  <--- 本协议原始报文 --->  WIoTa 网关（透明传输）  <--- 本协议原始报文 --->  服务器
```

设计原则：

- 采用 `Property + Destination Address Segment + Packet Number + Cmd + Data` 结构。
- 不携带源地址；可选目标地址段支持同时携带多个 4 字节终端地址。
- 包序号固定为 1 字节；不设置应用层帧头、长度和 CRC。
- 报文边界及校验由 WIoTa 数据包和网关至服务器的承载协议保证。
- 所有多字节整数使用小端序，所有结构按 1 字节对齐，禁止编译器自动填充。
- 正常帧 Data 长度为 0～298 字节，当前已定义命令的最大 Data 为 29 字节。整帧必须在一条承载消息中完整传输。

## 2. 编码约定

| 类型 | 长度 | 说明 |
| --- | ---: | --- |
| `uint8` / `int8` | 1 字节 | 无符号/有符号 8 位整数 |
| `uint16` / `int16` | 2 字节 | 小端序；有符号数使用二进制补码 |
| `int24` | 3 字节 | 小端序有符号 24 位整数，使用二进制补码 |
| `uint32` / `int32` | 4 字节 | 小端序；有符号数使用二进制补码 |
| `version16` | 2 字节 | `bit15..12=major`，`bit11..8=minor`，`bit7..0=patch` |

例如版本 `V1.2.3` 编码为 `0x1203`，线上字节为 `03 12`。`major`、`minor` 的取值范围均为 0～15，`patch` 为 0～255。

### 2.1 物理量编码

| 字段 | 类型 | 单位/范围 | 无效值 |
| --- | --- | --- | --- |
| UTC 时间 | `uint32` | Unix 时间戳，单位 s，UTC | `0` |
| 经度 | `int32` | 实际经度 × 1,000,000，东经为正 | `0x80000000` |
| 纬度 | `int32` | 实际纬度 × 1,000,000，北纬为正 | `0x80000000` |
| 海拔 | `int24` | 0.1 m，可表示约 -838.8～+838.8 km | `0x800000` |
| HDOP | `uint8` | 实际 HDOP × 10，最大 25.4 | `0xFF` |
| 电池电压 | `uint16` | 1 mV | `0xFFFF` |
| X/Y/Z 轴倾角 | `int16` | 0.01°，有效范围 -90.00°～+90.00° | `0x8000` |
| WIoTa SNR | `int8` | 1 dB | `0x80` |

## 3. 帧格式

### 3.1 帧结构

```text
+----------+------------------------------+---------------+---------+----------+
| Property | Destination Address Segment? | Packet Number | Cmd     | Data     |
| 1 Byte   | 0 或 1+4×N Bytes            | 1 Byte        | 1 Byte  | N Bytes  |
+----------+------------------------------+---------------+---------+----------+
```

字段严格按上图顺序出现。`Property` 只指示可选地址字段是否存在；`Packet Number` 和 `Cmd` 始终存在。`Data` 的长度由 `Cmd`、请求/响应方向及承载层报文总长度共同确定。

### 3.2 Property

| 位 | 名称 | 为 1 时的含义 |
| ---: | --- | --- |
| 7 | `HAS_DST` | 存在可选目标地址段 `Destination Address Segment` |
| 6 | `RESERVED` | 保留，发送时固定为 0 |
| 5 | `RESERVED` | 保留，发送时固定为 0 |
| 4 | `ACK_REQ` | 请求对端响应 |
| 3 | `IS_RESP` | 当前报文是响应 |
| 2 | `RESERVED` | 保留，发送时固定为 0 |
| 1 | `COMPRESSED` | 压缩标识；本协议固定为 0 |
| 0 | `RESERVED` | 保留，发送时固定为 0 |

常用 `Property` 值：

| 值 | 使用场景 | 目标地址段 |
| --- | --- | --- |
| `0x00` | 终端主动上报，不要求响应 | 无 |
| `0x10` | 请求对端响应，不携带目标地址 | 无 |
| `0x08` | 响应 | 无 |
| `0x80` | 服务器下行携带目标地址，不要求响应 | 有 |
| `0x90` | 服务器下行携带目标地址，要求响应 | 有 |

### 3.3 地址

本协议不携带源地址。终端来源由 WIoTa 承载链路上下文标识，网关不把该信息写入或修改本协议报文。

可选目标地址段仅用于服务器下行组播，其结构如下：

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | Address Count | `uint8` | 目标地址个数 N，范围 1～255 |
| 1 | 4×N | Address List | `uint32[N]` | 目标终端地址列表，每个地址 4 字节、小端序 |

- 一个终端 Address 固定为 4 字节，由生产或入网系统分配，必须全网唯一。
- `0x00000000` 和 `0xFFFFFFFF` 为保留地址，不得出现在地址列表中；同一列表内地址不得重复。
- 多终端寻址或组播时必须携带目标地址段，各终端只处理列表中包含自身地址的报文。
- 上下行单播或短消息不存在组播时，可以不携带地址段，由承载链路上下文确定终端身份和路由。
- 地址数量受承载层单条消息最大长度限制，整帧不得拆分。

### 3.4 请求与响应

- `Packet Number` 范围为 1～255。发送方递增使用，255 后回绕到 1。
- 请求和响应使用相同的 `Packet Number` 与 `Cmd`，通过 `IS_RESP` 区分。
- `ACK_REQ=1` 的报文必须响应。响应报文的 `ACK_REQ` 必须为 0，且不得再次要求响应。
- 主动周期上报默认 `ACK_REQ=0`，以减少空口开销。
- 响应按承载链路终端身份、`Packet Number` 和 `Cmd` 与请求配对。
- 对携带多个目标地址的请求，各目标终端分别响应，响应不携带地址段。
- 同一报文重发时必须保持原 `Packet Number` 不变。接收方应缓存近期处理结果，收到重复请求时返回原响应，不得再次执行设置或重启。
- 主动上报重发时保持原序号；产生一条新的采样记录时使用新序号。

### 3.5 数据边界与校验

一条本协议帧必须完整放入一条 WIoTa 应用数据包。网关转发到 MQTT 等承载协议时，也必须保持一条消息对应一帧。接收端从承载层取得总长度后，按命令规定校验 Data 长度。

- 正常帧 Data 长度不得超过 298 字节。该长度只计算 Data，不包含 Property、目标地址段、Packet Number 和 Cmd。
- Data 可以为 0 字节；所有查询请求的 Data 固定为 0 字节。
- 省略目标地址段时，正常帧总长度不得超过 301 字节。
- 携带 N 个目标地址时，整帧总长度为 `4 + 4×N + Data长度` 字节，并且不得超过承载层单条消息的长度限制。
- 本协议不重复增加帧头、长度或 CRC。若后续用于不提供消息边界或校验的裸串口链路，必须在本协议外另加串口封装层。

### 3.6 查询请求

所有查询请求均不携带 Data，`Cmd` 后立即结束。当前查询请求包括：`0x01` 查询设备信息和 `0x03` 查询上报周期。收到携带 Data 的查询请求时，终端应视为长度错误。

## 4. 命令总表

| 分类 | Cmd | 命令 | 发起方 | 请求 Data | 响应 Data |
| --- | --- | --- | --- | ---: | ---: |
| 设备接入 | `0x01` | 设备注册/查询设备信息 | 终端或服务器 | 注册 29 字节；查询不携带 Data | 注册确认 1 字节；查询响应 29 字节 |
| 数据上报 | `0x02` | 上报倾角定位 | 终端 | 25 字节 | 通常无响应；要求响应时 1 字节 |
| 上报配置 | `0x03` | 查询上报周期 | 服务器 | 不携带 Data | 4 字节 |
| 上报配置 | `0x04` | 设置上报周期 | 服务器 | 4 字节 | 4 字节 |
| 设备控制 | `0x05` | 重启终端 | 服务器 | 0 字节 | 1 字节 |
| 通信配置 | `0x06` | 设置终端功率和频点列表 | 服务器 | 3～10 字节 | 4～11 字节 |
| 传感器配置 | `0x07` | 设置 Gsensor 加速度计测量范围 | 服务器 | 1 字节 | 2 字节 |

## 5. 命令定义

响应中出现 `Status` 时统一取值：`0x00` 成功，`0x01` 命令不支持，`0x02` Data 长度错误，`0x03` 参数错误，`0x04` 执行失败，`0x05` 持久化失败，`0x06` 设备忙。

### 5.1 设备注册/查询设备信息（Cmd `0x01`）

终端首次开机并接入 WIoTa 网络后主动发送注册请求。服务器也可随时发送空 Data 请求，主动查询同一份设备信息。

#### 5.1.1 终端注册请求/查询响应 Data

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 4 | UTC | `uint32` | 世界时间，Unix 时间戳，单位 s |
| 4 | 4 | Longitude | `int32` | 经度 × 1,000,000 |
| 8 | 4 | Latitude | `int32` | 纬度 × 1,000,000 |
| 12 | 3 | Altitude | `int24` | 海拔，单位 0.1 m |
| 15 | 1 | HDOP | `uint8` | 水平精度因子 × 10 |
| 16 | 2 | Angle X | `int16` | X 轴倾角，单位 0.01° |
| 18 | 2 | Angle Y | `int16` | Y 轴倾角，单位 0.01° |
| 20 | 2 | Angle Z | `int16` | Z 轴倾角，单位 0.01° |
| 22 | 2 | HW Version | `version16` | 硬件版本 |
| 24 | 2 | APP Version | `version16` | 终端应用固件版本 |
| 26 | 2 | WIoTa Version | `version16` | WIoTa 模组固件版本 |
| 28 | 1 | WIoTa SNR | `int8` | 最近一次接入/通信 SNR，单位 dB |

Data 固定为 29 字节。无效数据使用 2.1 节规定的无效值表示。注册确认响应 Data 为 1 字节 `Status`；查询设备信息请求不携带 Data，查询响应使用上表 29 字节 Data。

注册未收到成功响应时，终端可重发相同注册内容；建议采用退避策略，避免持续占用空口。

**示例：** `Packet Number=0x01` 的注册请求及成功响应：

```text
终端注册：10 01 01 A4 E6 E9 67 74 15 F0 06 6E F7 60 02 F4 01 00 08 D2 04 C9 FD 0C 00 00 10 03 12 00 15 0A
服务器响应：08 01 01 00
```

**注册请求分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `10` | Property | 要求服务器响应，不携带目标地址 |
| `01` | Packet Number | 包序号 1 |
| `01` | Cmd | 设备注册/查询设备信息 |
| `A4 E6 E9 67` | UTC | Unix 时间戳 `0x67E9E6A4` |
| `74 15 F0 06` | Longitude | 116.397428° |
| `6E F7 60 02` | Latitude | 39.909230° |
| `F4 01 00` | Altitude | 50.0 m |
| `08` | HDOP | 0.8 |
| `D2 04` | Angle X | +12.34° |
| `C9 FD` | Angle Y | -5.67° |
| `0C 00` | Angle Z | +0.12° |
| `00 10` | HW Version | V1.0.0 |
| `03 12` | APP Version | V1.2.3 |
| `00 15` | WIoTa Version | V1.5.0 |
| `0A` | WIoTa SNR | 10 dB |

**注册响应分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `08` | Property | 响应，不携带目标地址 |
| `01` | Packet Number | 复制请求包序号 1 |
| `01` | Cmd | 设备注册/查询设备信息 |
| `00` | Status | 注册成功 |

`Packet Number=0x02` 的设备信息查询请求不携带 Data：

```text
服务器查询：10 02 01
终端响应：08 02 01 A4 E6 E9 67 74 15 F0 06 6E F7 60 02 F4 01 00 08 D2 04 C9 FD 0C 00 00 10 03 12 00 15 0A
```

**查询请求分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `10` | Property | 要求终端响应，不携带目标地址 |
| `02` | Packet Number | 包序号 2 |
| `01` | Cmd | 查询设备信息；Cmd 后结束，无 Data |

**查询响应分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `08` | Property | 响应，不携带目标地址 |
| `02` | Packet Number | 复制请求包序号 2 |
| `01` | Cmd | 设备注册/查询设备信息 |
| 后续 29 字节 | 设备信息 Data | 字段解释与上方注册请求 Data 相同 |

### 5.2 上报倾角定位（Cmd `0x02`）

终端按上报周期唤醒并主动发送最新 GNSS 定位和倾角数据，不携带地址段。

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | Flags | `uint8` | bit0：GNSS 有效；bit1：UTC 有效；bit2：Gsensor 有效；bit7..3：0 |
| 1 | 4 | UTC | `uint32` | 世界时间，Unix 时间戳，单位 s |
| 5 | 4 | Longitude | `int32` | 经度 × 1,000,000 |
| 9 | 4 | Latitude | `int32` | 纬度 × 1,000,000 |
| 13 | 3 | Altitude | `int24` | 海拔，单位 0.1 m |
| 16 | 1 | HDOP | `uint8` | 水平精度因子 × 10 |
| 17 | 2 | Battery Voltage | `uint16` | 电池电压，单位 mV |
| 19 | 2 | Angle X | `int16` | X 轴倾角，单位 0.01° |
| 21 | 2 | Angle Y | `int16` | Y 轴倾角，单位 0.01° |
| 23 | 2 | Angle Z | `int16` | Z 轴倾角，单位 0.01° |

Data 固定为 25 字节。默认使用 `Property=0x00`，整个应用层报文为 28 字节。若业务要求确认，使用 `Property=0x10`，服务器以 1 字节状态响应。

**示例：** `Packet Number=0x03`，全部数据有效，终端主动上报且不要求响应：

```text
00 03 02 07 A4 E6 E9 67 74 15 F0 06 6E F7 60 02 F4 01 00 08 E4 0C D2 04 C9 FD 0C 00
```

**上报帧分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `00` | Property | 主动上报，不要求响应，无目标地址 |
| `03` | Packet Number | 包序号 3 |
| `02` | Cmd | 上报倾角定位 |
| `07` | Flags | GNSS、UTC、Gsensor 数据均有效 |
| `A4 E6 E9 67` | UTC | Unix 时间戳 `0x67E9E6A4` |
| `74 15 F0 06` | Longitude | 116.397428° |
| `6E F7 60 02` | Latitude | 39.909230° |
| `F4 01 00` | Altitude | 50.0 m |
| `08` | HDOP | 0.8 |
| `E4 0C` | Battery Voltage | 3300 mV（3.3 V） |
| `D2 04` | Angle X | +12.34° |
| `C9 FD` | Angle Y | -5.67° |
| `0C 00` | Angle Z | +0.12° |

### 5.3 查询上报周期（Cmd `0x03`）

服务器查询请求不携带 Data，`Cmd` 后立即结束。终端响应 Data 如下：

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 4 | Period | `uint32` | 当前实际生效的上报周期，单位 s |

为节省 1 字节，本命令响应不携带状态字节。

**示例：** `Packet Number=0x04`，查询请求不携带 Data，终端返回 14400 s：

```text
服务器查询：10 04 03
终端响应：08 04 03 40 38 00 00
```

**查询请求分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `10` | Property | 要求终端响应，不携带目标地址 |
| `04` | Packet Number | 包序号 4 |
| `03` | Cmd | 查询上报周期；Cmd 后结束，无 Data |

**查询响应分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `08` | Property | 响应 |
| `04` | Packet Number | 复制请求包序号 4 |
| `03` | Cmd | 查询上报周期 |
| `40 38 00 00` | Period | 14400 s（4 h） |

### 5.4 设置上报周期（Cmd `0x04`）

服务器请求和终端响应使用相同的数据结构：

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 4 | Period | `uint32` | 上报周期，单位 s，有效范围 2～259200 |

- 默认值为 14400 s（4 h），最短为 2 s，最长为 259200 s（72 h）。
- 终端必须先校验并持久化参数，成功后再更新运行时定时器。
- 终端始终响应实际生效的周期。若请求值非法或保存失败，配置保持不变，并返回原周期；服务器通过比较请求值和响应值判断是否设置成功。
- 为节省 1 字节，本命令响应不携带状态字节。

**示例：** `Packet Number=0x05`，设置上报周期为 2 s：

```text
服务器请求：10 05 04 02 00 00 00
终端响应：08 05 04 02 00 00 00
```

**设置请求分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `10` | Property | 要求终端响应，不携带目标地址 |
| `05` | Packet Number | 包序号 5 |
| `04` | Cmd | 设置上报周期 |
| `02 00 00 00` | Period | 设置为 2 s |

**设置响应分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `08` | Property | 响应 |
| `05` | Packet Number | 复制请求包序号 5 |
| `04` | Cmd | 设置上报周期 |
| `02 00 00 00` | Period | 实际生效周期为 2 s |

### 5.5 重启终端（Cmd `0x05`）

服务器请求 Data 为空。终端响应 Data 为 1 字节状态。

终端必须先发送 `OK` 响应，确认报文已交给 WIoTa 发送流程后再执行软件重启。请求长度错误或设备正忙时返回相应错误状态，不执行重启。对重复的包序号必须返回原处理结果，不得再次执行重启。

**示例：** `Packet Number=0x06`，请求重启并成功响应：

```text
服务器请求：10 06 05
终端响应：08 06 05 00
```

**重启请求分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `10` | Property | 要求终端响应，不携带目标地址 |
| `06` | Packet Number | 包序号 6 |
| `05` | Cmd | 重启终端；Cmd 后结束，无 Data |

**重启响应分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `08` | Property | 响应 |
| `06` | Packet Number | 复制请求包序号 6 |
| `05` | Cmd | 重启终端 |
| `00` | Status | 已接受重启命令 |

### 5.6 设置终端功率和频点列表（Cmd `0x06`）

#### 5.6.1 请求 Data

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | TX Power | `int8` | 终端发射功率，单位 dBm，有效范围 -16～+22 |
| 1 | 1 | Freq Count | `uint8` | 频点数量 N，有效范围 1～8 |
| 2 | N | Freq List | `uint8[N]` | WIoTa 频点索引，每项范围 0～200 |

请求 Data 长度必须严格等于 `2 + N`。频点不得重复，`0xFF` 结束符不发送，因为 `Freq Count` 已明确列表长度。

#### 5.6.2 响应 Data

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | Status | `uint8` | 执行状态，见本章开头 |
| 1 | 1 | TX Power | `int8` | 当前持久化的发射功率 |
| 2 | 1 | Freq Count | `uint8` | 当前持久化的频点数量 N |
| 3 | N | Freq List | `uint8[N]` | 当前持久化的频点列表 |

- 终端必须对功率和完整频点列表做整体校验及原子保存，禁止只应用部分字段。
- 设置成功时返回新配置；失败时返回错误状态和原配置。
- 为避免修改频点后丢失响应，终端应先使用当前链路发送响应，再在下一次入网或重启后应用新频点列表。

**示例：** `Packet Number=0x07`，向地址 `0x12345678`、`0x9ABCDEF0` 设置 10 dBm 和频点列表 `[160, 161, 162]`：

```text
服务器请求：90 02 78 56 34 12 F0 DE BC 9A 07 06 0A 03 A0 A1 A2
终端响应：08 07 06 00 0A 03 A0 A1 A2
```

**设置请求分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `90` | Property | 携带目标地址并要求响应 |
| `02` | Address Count | 2 个目标地址 |
| `78 56 34 12` | Address[0] | `0x12345678` |
| `F0 DE BC 9A` | Address[1] | `0x9ABCDEF0` |
| `07` | Packet Number | 包序号 7 |
| `06` | Cmd | 设置终端功率和频点列表 |
| `0A` | TX Power | 10 dBm |
| `03` | Freq Count | 3 个频点 |
| `A0 A1 A2` | Freq List | 频点 160、161、162 |

**设置响应分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `08` | Property | 响应，不携带目标地址 |
| `07` | Packet Number | 复制请求包序号 7 |
| `06` | Cmd | 设置终端功率和频点列表 |
| `00` | Status | 设置成功 |
| `0A` | TX Power | 当前功率 10 dBm |
| `03` | Freq Count | 当前有 3 个频点 |
| `A0 A1 A2` | Freq List | 当前频点 160、161、162 |

两个目标终端分别返回相同格式的响应，服务器通过承载链路终端身份区分。

### 5.7 设置 Gsensor 加速度计测量范围（Cmd `0x07`）

#### 5.7.1 请求 Data

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | Range | `uint8` | 加速度计测量范围枚举 |

| Range | 测量范围 |
| ---: | --- |
| `0x00` | ±2g |
| `0x01` | ±4g |
| `0x02` | ±8g |
| `0x03` | ±16g |

默认值为 `0x00`（±2g）。

#### 5.7.2 响应 Data

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | Status | `uint8` | 执行状态，见本章开头 |
| 1 | 1 | Range | `uint8` | 当前实际生效的测量范围 |

终端应先校验并持久化设置，再重新配置 Gsensor。成功时返回新量程；失败时保持原配置并返回原量程。

**示例：** `Packet Number=0x08`，设置量程为 ±8g：

```text
服务器请求：10 08 07 02
终端响应：08 08 07 00 02
```

**设置请求分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `10` | Property | 要求终端响应，不携带目标地址 |
| `08` | Packet Number | 包序号 8 |
| `07` | Cmd | 设置 Gsensor 加速度计测量范围 |
| `02` | Range | 设置为 ±8g |

**设置响应分析：**

| 字节 | 字段 | 解释 |
| --- | --- | --- |
| `08` | Property | 响应 |
| `08` | Packet Number | 复制请求包序号 8 |
| `07` | Cmd | 设置 Gsensor 加速度计测量范围 |
| `00` | Status | 设置成功 |
| `02` | Range | 当前量程为 ±8g |
