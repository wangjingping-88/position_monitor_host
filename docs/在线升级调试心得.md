# 倾角定位上位机 GitHub Release 升级验证

日期：2026-10-10。源码：`D:\code\position_monitor_host`。方案参考 `D:\code\ota_tool`。

## 区分检查、下载和安装

仓库公开和 Git 标签存在不等于可更新。`releases/latest` 只有正式 Release 才返回内容，404 应显示“尚未发布正式版”，不能显示“当前最新版”。新版本需要 ZIP 和 SHA-256 文本两个资产，并核对 GitHub digest、文件大小、校验文本与实际 ZIP 摘要。

用假 HTTP 响应验证版本比较、缺少资产、损坏下载和取消；用真实独立更新器验证目录切换和新程序启动，分开定位网络、文件系统与 UI 生命周期问题。

## 便携配置迁移时机

配置放在程序旁的 data 目录，单纯目录替换会丢失配置。更新包不能包含 data；等待旧进程退出后再把原 data 复制到暂存目录，避免复制到尚未完成写入的配置。嵌套目录也要保留，拒绝跟随链接。旧安装备份只在新版确认启动后删除；新版失败则恢复旧目录及原配置。

## WPF 与更新器生命周期

下载时冻结新下行控制和连接变更，但保持监控接收。等待中的控制命令需先完成。下载可取消；取消已准备好的更新也要清除暂存任务和待安装状态。校验后先关闭 MQTT，再启动安装目录外的独立更新器，由其等待原进程退出，避免 DLL 占用。

主窗口完成布局后写入启动确认，更新器超时则回滚。自包含单文件更新器的原生库解压路径通过 DOTNET_BUNDLE_EXTRACT_BASE_DIR 指向 D 盘，避免默认写入 C 盘临时目录。
