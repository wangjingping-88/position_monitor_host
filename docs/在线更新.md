# GitHub Release 在线更新

当前版本：v0.1.1。仓库为公开仓库，程序无需 GitHub Token。

## 使用方法

点击菜单栏“检查更新”。窗口显示当前版本、新版本、发布时间、下载大小和更新说明；有可安装的新版本时，“下载并安装”可用。仅检查最新正式 Release，跳过草稿和预发布版本。

下载阶段可以取消，正常监控继续运行，暂时禁用新的连接设置及下行控制操作。如果有下行命令正在等待响应，需等执行结束后再安装。校验成功后断开 MQTT，启动独立更新器并关闭旧程序。新版正常打开主窗口后完成启动确认；更新器在 60 秒内未收到确认时自动恢复旧版并重新启动。

安装采用同卷目录切换。原程序退出后复制原安装目录的整个 `data` 目录，因此保留 `data/connection.json` 及嵌套配置；Windows 凭据管理器中的密码不改动。暂存、备份目录位于安装目录旁，下载、任务、更新日志和更新器运行副本位于 `D:\Program Files\PositionMonitorHost\updates`。该目录及安装目录的父目录需可写。

更新逻辑参考 `ota_tool` 的独立更新库、更新器和目录回滚方案，并增加上位机便携配置迁移。下载分别核对 GitHub 资产摘要、校验文件及实际大小；拒绝不属于本仓库的资产链接、ZIP 路径穿越、符号链接、超量解压和包内 `data` 目录。

## 发布新版本

1. 修改 `Directory.Build.props` 的 `Version`，例如 `0.1.2`，补充版本记录与发布说明。
2. 运行 `scripts/PackageRelease.ps1`，先构建并测试，再从全新目录发布自包含包。此脚本只准备本地文件，不提交代码、不创建标签、不上传 Release。
3. 经确认后提交并推送代码，创建和推送 `v0.1.2` 标签，在 GitHub 创建该标签的正式 Release。
4. 上传打包生成的两个文件：`PositionMonitor-v0.1.2-win-x64-portable.zip` 和 `PositionMonitor-v0.1.2-win-x64-portable.zip.sha256.txt`。二者均须有 GitHub 自动生成的 `sha256:` digest。必须保留准确命名，不能上传手工压缩整个目录的包。
5. 在旧版点击“检查更新”，核对版本、说明和安装结果。首次支持在线更新的版本为 v0.1.1；v0.1.0 需手动换用新便携包。

日常预览仍固定发布到 `D:\code\position_monitor_host\publish\win-x64`。Release 文件位于 `artifacts/releases/v版本号`，不包含本地连接账号、用户配置或调试截图。

## 验证

`scripts/Build.ps1` 包含 13 项更新验证，覆盖严格版本比较、检查节流、缺少资产、下载与双重摘要校验、取消清理、安全解压、启动确认、配置保留、退出超时及回滚。另有 78 项原有协议、回环 MQTT 和 WPF 联调验证。

生成包后执行 `scripts/VerifyUpdate.ps1`，在专用夹具目录运行真实自包含更新器，检查新版 WPF 启动确认、连接配置保留及备份清理。夹具不会连接现场服务器，也不会替换日常预览目录。实际 GitHub 下载仍需已发布的完整正式 Release。

## 尚无 Release 或网络失败

仅创建 Git 标签不足以支持更新，必须创建正式 Release 并上传完整资产。仓库没有正式 Release 时显示“尚未发布正式版”，保留当前程序；网络错误、限流、资源缺失或摘要不一致也不会替换程序。可使用“发布页”核对版本，排查日志位于更新目录的 `logs/update-check.log` 和 `logs/updater.log`。
